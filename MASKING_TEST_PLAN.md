# Следующий этап: локальная маскировка текста

Статус: реализован локальный этап, проверки находятся в `tests/test_privacy_cli.py`. Пользователь разрешил продолжать разработку и выбирать проверки самостоятельно. Подключение Qwen и облачного анализатора в этот этап не входит.

## Что получим

Локальный текст задачи или текстового отчёта обрабатывается по справочнику сотрудников. Известные ФИО, варианты имён, логины, почты и телефоны заменяются постоянными метками. Прежние значения из истории справочника также учитываются. В готовом ответе метки восстанавливаются в имена локально.

Содержимое кода и файлов отчётов сохраняет ранее согласованные исключения. На этом этапе обрабатывается текст, а не PDF/DOCX или репозиторий. Внешние системы и облако пока не подключаются.

## Предлагаемый способ проверки

Проверять через новые команды терминала отдельными процессами с временным справочником, входными текстами и локальным каталогом запуска. Не вызывать внутренние функции или читать таблицы напрямую. Это проверяет весь локальный путь обработки текста, но не плагин LM Studio, внешние источники или анализатор.

Предлагаемые команды:

```text
python -m privacy --db <registry.sqlite> prepare <input.txt> --run-dir <local-run-dir>
python -m privacy inspect <local-run-dir>
python -m privacy decide <local-run-dir> continue|skip
python -m privacy restore <local-run-dir> <answer.txt> --output <report.txt>
```

Команды реализованы; у decide требуется `--version` из prepare/inspect. Добавлена команда `export <local-run-dir> --output <file>`: только она выдаёт текст для дальнейшей передачи после проверки состояния и версии. Подключение локальной Qwen для действия «Очистить» будет отдельным шагом. Пока отправки в облако нет, continue означает локальное разрешение конкретной версии, а не фактическую отправку.

## Правила

- Длинное совпадение обрабатывается раньше короткого; текст не заменяется повторно внутри уже созданных меток.
- Совпадение должно учитывать границы слова/логина, регистр и распространённое форматирование телефона. Не заменять часть другого слова.
- Общий вариант имени или одинаковое ФИО у нескольких людей не сопоставлять случайному сотруднику: остановка с найденным фрагментом и причиной.
- Не выводить весь справочник или локальные соответствия в подготовленный материал. Хранить их только в локальных данных запуска.
- Повторная проверка остатков выполняется скриптом, независимо от способа очистки.
- Найденные неизвестные адреса/телефоны не приписывать сотруднику по догадке. Поведение проверки по регулярным выражениям нужно явно отразить в результате, без обещания выявить любые персональные данные.
- Решение «Продолжить» привязано к показанной версии материала; изменение материала требует новой проверки/решения. «Пропустить» не создаёт готовый к отправке материал.
- Восстановление заменяет только точные известные метки. Неизвестную метку не превращать в предполагаемое имя.
- Материалы запуска остаются локально до завершения запроса; готовые отчёты не удаляются.

## Последовательные шаги TDD

1. Подготовка текста по справочнику и восстановление имени через команды.
2. Исторические имена/аккаунты, границы совпадений и форматирование контактов.
3. Неоднозначные совпадения и повторная проверка: остановка с локальной диагностикой.
4. Решения continue/skip и привязка разрешения к конкретному материалу.
5. Защита от неизвестных меток и от выдачи локальных соответствий вместе с подготовленным текстом.

Каждая новая возможность начинается одним падающим тестом команды, затем реализуется минимально и проверяется снова. Функциональность справочника должна продолжать проходить существующие проверки Windows. Linux остаётся основной средой эксплуатации и отдельной будущей проверкой запуска.
