# Запуск анализатора

Для новой цепочки Bitrix из чата используйте [BITRIX_LIVE.md](../BITRIX_LIVE.md): Codex подключён к очереди через отдельный daemon и Unix-сокет; предусмотрен отдельный device login по подписке. Ниже описаны сохранённые самостоятельные адаптеры с API-ключами, их ограничения не означают отсутствие нового режима. Реальный вход и изоляция новых контейнеров ещё требуют проверки пользователем.

Поддерживаются три значения kind: chat_completions, codex_cli, claude_code. Выбор делает разработчик в JSON-конфигурации. Публичная команда одна:

```powershell
python -m analyzer --config data/analyzer.local.json --input data/handoff.json --output data/answer.json
```

handoff.json должен быть создан командой privacy export --bundle после локальной проверки/разрешения. Сырые выгрузки integrations сюда не подходят. Существующий output не перезаписывается. Ответ всех адаптеров одинаков: summary и findings. Неизвестные метки/источники, ошибки процесса и незавершённые ответы отклоняются. Автоматической смены провайдера нет.

## Codex CLI и Claude Code

Адаптеры реализованы, проверены на Windows подставными процессами без внешних запросов. Рабочая схема предназначена для Linux-контейнеров, в том числе Docker Desktop. Настоящая сборка Docker и подключение CLI к провайдерам в этой среде не проверены: Docker и Claude Code не установлены. До проверки не объявлять эксплуатационную изоляцию подтверждённой.

На доверенном хосте нужны Docker с Linux-контейнерами и Python. Docker socket не передаётся приложению или анализатору. Эта команда запускается на доверенном хосте; её ещё не вызывает HTTP-очередь проекта.

1. Собрать образ с проверенными точными версиями CLI (вместо X.Y.Z и A.B.C указать выбранные версии, поддерживающие перечисленные ниже параметры):

```text
docker build -f Dockerfile.cli-analyzer --build-arg CODEX_VERSION=X.Y.Z --build-arg CLAUDE_VERSION=A.B.C -t worklog-cli-analyzer:local .
```

Сборка скачивает зависимости. Она отделена от обработки материалов и не получает ключи провайдера. Во время анализа автоматической загрузки образов нет. Образ должен быть доверенным и содержать только код анализатора и зависимости; не добавлять в него конфиденциальные данные или пользовательские настройки.

2. Запустить шлюз только выбранного провайдера:

```text
docker compose -f compose.analyzer-gateway.yaml --profile codex up -d --build codex-gateway
```

Для Claude заменить codex на claude, а codex-gateway на claude-gateway.

3. Скопировать examples/analyzer-codex.json либо examples/analyzer-claude.json в data/analyzer.local.json. Указать модель, доступную выбранной учётной записи. Имена томов уже соответствуют Compose. Параметр timeout_seconds ограничен диапазоном 1–1800 секунд.

4. Передать собственный ключ только выбранного провайдера через окружение процесса запуска:

```powershell
$env:CODEX_API_KEY = "ваш ключ OpenAI"
# Либо для Claude Code:
$env:ANTHROPIC_API_KEY = "ваш ключ Anthropic"
```

Эта версия использует API-ключи. Она не копирует вход в установленный на компьютере Codex/Claude Code и не использует автоматически подписку пользователя. OAuth/перенос пользовательских auth.json не подключены. Ключи источников анализатору не передаются, ключи не включаются в аргументы запуска или JSON материалов.

5. Выполнить общую команду python -m analyzer выше. Для проверки используйте только вымышленные материалы, затем подтвердите работу выбранных версий CLI и сети на целевом Linux.

## Что ограничивает запуск

- На каждый запрос создаётся новый контейнер с network=none, read-only корнем, непривилегированным пользователем, без capabilities, с no-new-privileges и ограничениями памяти/CPU/числа процессов.
- Папки проекта, справочник, домашний каталог пользователя и Docker socket не монтируются. Материалы поступают через stdin. Временные файлы CLI находятся в tmpfs и исчезают вместе с контейнером; результат возвращается через stdout.
- Единственный общий том — выделенный том с Unix-сокетом шлюза, подключённый только для чтения. Не хранить там файлы приложения. Шлюз не имеет ключей и материалов на диске.
- CLI использует локальный HTTP CONNECT-прокси, который передаёт соединение через Unix-сокет. Прямого сетевого интерфейса у анализатора нет. Шлюз допускает только api.openai.com:443 либо api.anthropic.com:443, в зависимости от выбранного шлюза. Другие домены, IP-литералы, порты и непубличные результаты DNS блокируются. TLS не расшифровывается шлюзом.
- Если провайдер перенаправит запрос на другой домен, он будет заблокирован. Дополнительные endpoints, прокси компании, OAuth и региональные API требуют отдельной настройки и проверки; автоматического расширения доступа нет.
- Для Claude заданы bare, пустой tools и пустая строгая конфигурация MCP; MCP-серверы не подключаются. Для Codex отключены shell_tool и web_search, включён read-only sandbox; настройки хоста отсутствуют в новом HOME.
- При таймауте хост пытается принудительно удалить свой контейнер. При недоступности Docker daemon очистка не гарантирована: после восстановления проверить контейнеры worklog-analysis-*. Убийство самого host-runner и аварийное выключение требуют отдельной процедуры восстановления.

## Перед эксплуатацией

На целевом Linux проверить: сборку точных версий, поддержку параметров CLI, доступ через CONNECT-прокси, разрешение сокета из read-only тома, запрет прямого доступа к интернету/хосту/корпоративным адресам, отсутствие исходных файлов и ключей в контейнере, очистку после успеха/ошибки/таймаута. Проверить sandbox Codex при стандартном Docker seccomp; при ошибке не отключать изоляцию, а выяснить несовместимость версий.

Официальные источники параметров: [Codex non-interactive](https://learn.chatgpt.com/docs/non-interactive-mode), [Codex configuration](https://learn.chatgpt.com/docs/config-file/config-reference), [Claude Code CLI](https://code.claude.com/docs/en/cli-reference). Возможность запуска конкретной модели/учётной записи должна проверяться отдельно.
