# Состояние реализации

## Последние ручные проверки пользователя

- В get_employee_statistics добавлены отдельные completed_tasks/current_tasks с названиями и ссылками Bitrix; просрочка в сводке остаётся только counts.overdue. Сохраняются исходные массивы ключей и локальный расчёт. Для применения требуется пересборка service и переподключение MCP.

- По уточнению пользователя разделены локальная employee_statistics и облачная employee_review. Статистика не маскирует материалы, не запрашивает разрешение и не вызывает Codex; получение текстовых результатов Bitrix для неё отключено. MCP предоставляет отдельную analyze_employee_work. Облачный вопрос содержит название задачи, найденные данные и понятный выбор: «нет» → skip только показанной задачи, «Продолжить» → отправка показанной версии. Название и отказ сохраняются в отчёте. Требуется пересборка service и переподключение MCP; существующие старые ожидающие облачные запуски автоматически не изменяются.

- Для запуска f826e0e2a8ff4dd7962da4af0b011be7 подтверждено ожидание по задачам 570/608, а не массовый skip. Исправлена глобальная задержка: проверенные задачи анализируются, пока другие ждут решения; результаты сохраняются без повторной отправки. В MCP показывается одна задача за раз, решение имеет scope=single_task и журнал privacy_decision. Полный прогон после изменения: 140 тестов, OK, skipped=3 (71.409 секунды). Изменения требуют установки в контейнер и переподключения MCP, реальная работа обновлённой Qwen-цепочки ещё не подтверждена.

- Выяснена причина отказов normalize для задач 54 и 100: задержка записи NEW относительно создания на 74/45 секунд. Точное равенство заменено учётом history_valid_from; запросы, пересекающие неизвестный промежуток, остаются частичными. Все три сохранённые обезличенные структуры 54/100/1782 проходят нормализацию. Полный прогон после исправления: 135 тестов, OK, skipped=3 (51.709 секунды); дополнительная сентябрьская регрессия прошла вместе с 13 диагностическими тестами. Требуется пересборка service у пользователя. Полная цепочка настоящего Codex по-прежнему не подтверждена.

- Bionic подключился к MCP (Connected); запрос по Иванову вернул ожидаемую демонстрационную статистику 1/1/1/0. Наличие и открытие ссылки после последней правки отдельно не подтверждены. Это не проверка реальных источников через чат.
- Прямая выгрузка реальной задачи Bitrix 1782 прошла; пользователь сверил данные и подтвердил их правильность. Kaiten, GitLab и автоматический сбор списка задач через очередь этим не проверены.
- После повторной сборки Docker пользователь сообщил об успешном прохождении пакетных проверок. Детальный вывод этого повторного прогона в разговоре не представлен; прежние измеренные результаты ниже сохранены.

Упоминания ниже о непроверенном интерфейсе Bionic и отсутствии реальных запросов относятся к автоматическим проверкам до этих ручных действий. Автоматическая цепочка реальных источников, обезличивания и анализатора по-прежнему не собрана.

Проверочная среда: Windows, Python 3.13, Node.js 24. Основная целевая среда: Linux. Основной контейнер проверен пользователем в Docker Desktop. Вызов статистики из Bionic подтверждён на демонстрационных данных. Новая цепочка Bitrix → маскировка → Codex → восстановление → отчёт реализована; проверена на локальном HTTP Bitrix и подставном CLI, включая настоящий MCP-процесс. Новые контейнеры, Unix-сокеты и реальная подписка Codex требуют проверки Docker/Linux: доступ агента к Docker Engine запрещён. SDK LM Studio больше не используется. Инструкция — BITRIX_LIVE.md.

## Реализовано и проверено

| Часть | Что работает |
|---|---|
| Справочник | SQLite; add/list/edit/import через терминал; постоянные метки; история значений; дубликаты; подтверждение и атомарность импорта |
| Маскировка текста | Текущие/исторические ФИО, варианты, логины, почты и телефоны; отдельная проверка остатка; неоднозначности и неизвестные контакты; локальная диагностика |
| Решение по данным | continue/skip для показанной версии; запрет выгрузки без разрешения; изменение текста отменяет пригодность прежнего разрешения |
| Восстановление имён | Локальный снимок использованных меток; неизвестные метки останавливают сохранение; существующий файл не перезаписывается |
| Статистика | Нормализованная история; назначения в периоде; завершение/текущие на срезе; первое нарушение дедлайна; история переносов; единый UTC+5; неполная история отмечается |
| Запросы и отчёты | SQLite-очередь; атомарная защита от активного дубликата; локальное выполнение; постоянный JSON-отчёт; журнал этапов; очистка временных файлов завершённого запроса |
| HTTP | Только loopback; технический Bearer-токен; поиск сотрудников; запуск/статус/полный отчёт; фоновый обработчик |
| Просмотр отчёта | Подписанная ссылка на один документ на 10 минут; экранированный HTML; токен приложения в ссылку не попадает |
| MCP-переходник | Две фиксированные функции через stdio; handshake, progress, отмена ожидания, проверка аргументов, безопасные ошибки; сохранён проверенный HTTP-клиент. npm/SDK/Zod не используются. Проверен настоящий процесс MCP с локальным HTTP-сервисом |
| Текстовый анализатор | Конверт без маппинга; контроль версии; Chat Completions без инструментов; проверка структуры ответа, меток и источников; проверено только с локальным тестовым сервером |
| CLI-анализаторы | Адаптеры Codex exec и Claude Code print; единая валидация Findings; таймаут/ошибки/очистка; Docker-команда без сети и данных хоста; шлюз только к API провайдера. Проверены подставные CLI-процессы и локальные соединения, не реальные контейнеры |
| Прямые выгрузки | Bitrix: задача/результаты/история без чата. Kaiten: карточка/настроенное свойство отчёта. GitLab: авторство по почтам, период, diff и признак неполноты. Проверено на локальных тестовых HTTP-серверах |
| Реальная цепочка Bitrix | Список видимых задач с пагинацией; восстановление истории назначения/статуса/сроков; ISO и Unix-даты; исторический срез; локальная статистика; маскировка и блокировка; Codex через выделенный сокет; валидация и восстановление имён; сводка и постоянный отчёт |
| Решения в MCP | Опциональная privacy_decision для continue/skip/clean по задаче и версии; локальная Qwen предлагает замену первого проблемного значения, сервис повторно проверяет. Без вызова решения заблокированный материал не отправляется. Инструкция модели запрещает самостоятельное согласие |
| Восстановление после остановки | При запуске сервера running переводится в interrupted без автоматического повтора; его временные файлы очищаются. Ожидание решения по данным сохраняется |

Примеры явно демонстрационные. Сохраняется source_file для офлайн-проверок; source=bitrix включает новый реальный сбор. Подготовлена отдельная папка data/bitrix-live с копией справочника и настройками без вебхука. Исходный справочник не изменён. Сырые выгрузки Kaiten/GitLab автоматически не нормализуются.

## Подготовлено, но не проверено в целевой среде

- Dockerfile и Compose для локальных команд проверены в Docker Desktop: сборка, команды, SQLite, CSV, маскировка и статистика работают; данные сохраняются между контейнерами. HTTP-сервер в Compose по умолчанию не запускается, сеть отключена. На отдельном целевом Linux-хосте ещё не проверено.
- Tools Provider заменён MCP-переходником по решению пользователя. Исходники, manifest, npm-манифесты и сборки старого плагина удалены; общий HTTP-клиент перенесён в mcp-bridge. Старый node_modules остался неиспользуемым локальным артефактом: среда запретила рекурсивное удаление, его можно убрать вручную после остановки lms dev. В новом способе нет npm-зависимостей и Zod. Подготовлен data/lmstudio-demo/mcp-entry.json без значения токена; включение сервера и вызов инструментов из настоящего Bionic ещё требует пользовательской проверки. Инструкция — mcp-bridge/README.md.
- Образцы Kaiten/GitLab остаются непроверенными на реальных установках. Реальный Bitrix проверен пользователем отдельной выгрузкой; новая автоматическая цепочка с Codex в Docker пока проверена только локальными тестами. Вебхук задаётся пользователем через окружение и в файлы настроек не записывается.
- Отдельный Dockerfile.analyzer с минимальным набором кода и непривилегированным пользователем. Монтирования и принудительный сетевой контроль ещё не настроены/не проверены, поэтому образ не объявляется готовой изоляцией.
- Для CLI добавлены Dockerfile.cli-analyzer, Dockerfile.analyzer-gateway и compose.analyzer-gateway.yaml. Runner использует network=none и Unix-сокет шлюза вместо общей сети. Сборка, сокет между контейнерами, реальные версии CLI, ключи и фактическая изоляция на Linux ещё не проверены. Инструкция — analyzer/README.md.

Полный реальный список и особенности других историй требуют эксплуатационной проверки. Недостаточная история даёт частичный результат, не вымышленные показатели.
2. Скачивание и чтение файлов отчётов: текст, DOCX и текстовый PDF; корректный пропуск задачи при ошибке чтения.
3. Автоматический сбор материалов задачи, связь с GitLab по описанию/файлам и полный сценарий task_review/project_review.
4. Эксплуатационная проверка изоляции и авторизации на Linux/Docker. Для Bitrix Codex уже подключён к HTTP-очереди через отдельный network=none daemon, Unix-сокет и CONNECT-шлюз. Добавлена команда device login по подписке в отдельный Docker-том; реальный вход и настоящий ответ провайдера не проверены. Старые отдельные CLI-адаптеры с API-ключами сохранены, Claude Code к очереди не подключён.
5. Автоматическое сравнение кода и отчёта, разбиение больших материалов и проверка доказательств ответа.
6. Реальная проверка действий по персональным данным в интерфейсе Qwen. Серверные переходы, проверка версии и повторная проверка очистки реализованы и тестируются; фактическое поведение модели и отображение подтверждения нужно проверить пользователю.
7. Проверка аварийного завершения и восстановления на целевом Docker-хосте; логика interrupted и сохранения ожидающих материалов реализована и проверена локально.
8. Резервное копирование постоянной базы и эксплуатационная проверка на Linux/Docker.
