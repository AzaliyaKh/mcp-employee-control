# Проверки без Bitrix, GitLab, Kaiten и облака

Сейчас выбираем только проверки, для которых данные можно создать самостоятельно. Настоящие сотрудники, токены источников и доступ в интернет не нужны.

## Подготовка

Из корня проекта:

```powershell
python tools/generate_demo_data.py
```

Генератор создаёт новую папку `data/offline-demo` с двумя вымышленными сотрудниками в CSV, текстами для маскировки, ответом с метками, восемью задачами и отдельным примером неполной истории. Существующую папку не перезаписывает. Для повторного прогона можно задать `--output data/offline-demo-2`.

Для справочника используем только отдельную тестовую базу:

```powershell
python -m employees --db data/offline-demo/private/registry.sqlite import data/offline-demo/employees.csv
```

Подтвердить импорт словом «да». В этой новой базе появятся EMP_001 Тестов Алексей и EMP_002 Тестов Борис.

## Выбранные ручные проверки

| № | Что проверяем | Какие данные используем | Что должно получиться |
|---|---|---|---|
| 1 | Добавление и сохранение сотрудников | Вымышленные ФИО и аккаунты из employees.csv | После перезапуска записи и постоянные метки остаются |
| 2 | Редактирование | Дополнительно добавленный третий тестовый сотрудник | Имя меняется, метка сохраняется, старое значение остаётся в истории |
| 3 | Импорт и дубликаты | employees.csv повторно; conflict.csv | Повторные записи не добавляются; конфликт не сохраняет даже корректную часть файла |
| 4 | Маскировка | task.txt: известные ФИО, логин, почта и телефон | Все перечисленные сведения заменяются на EMP_001 |
| 5 | Остановка проверки | blocked.txt: общая фамилия двух людей и неизвестная почта | Показаны совпадения и причина, выгрузка без решения запрещена |
| 6 | «Продолжить» и «Пропустить» | Два отдельных запуска blocked.txt | Продолжить разрешает показанную версию; Пропустить запрещает выгрузку. Отправки в облако нет |
| 7 | Восстановление имён | answer.json и unknown-answer.txt | EMP_001 восстанавливается; EMP_999 вызывает ошибку, а не угадывание |
| 8 | Изменение после проверки | Дописать строку в candidate.txt отдельного тестового запуска | Старая проверка/разрешение больше не позволяет выгрузить файл |
| 9 | Статистика за период | tasks.json, интервал 1–31 октября 2026 | Назначено 7, завершено 1, впервые просрочено 3, текущих 6 |
| 10 | Неполные сведения | tasks-incomplete.json | partial=true, задача 109 в unavailable, точные показатели для неё не выдумываются |
| 11 | Сохранение отчётов и лог | Запрос к локальному приложению с config.json из сгенерированной папки | Отчёт сохраняется, журнал содержит этапы, временная папка завершённого запроса удаляется |
| 12 | Повторный запрос | Дважды создать одинаковый запрос до выполнения | Один run_id; после завершения можно создать новый, старый отчёт остаётся |
| 13 | HTTP-интерфейс | Локальный сервер и сгенерированная история | Поиск сотрудника, фоновые расчёты, сводка и открываемая ссылка на отчёт |

Подробные команды для пунктов 1–8, 11–13 — в `MANUAL_TEST_PLAN.md`. Подставляйте пути сгенерированного набора вместо examples/manual и используйте отдельную базу. Не редактируйте EMP_001 до проверки восстановления имён, иначе ожидаемое имя изменится.

## Проверка статистики с точным ответом

```powershell
python -m worklog statistics data/offline-demo/tasks.json --employee EMP_001 --start 2026-10-01 --end 2026-10-31
```

Сравнить с `data/offline-demo/expected.json`:

| Задача | Сценарий | Ожидаемое поведение |
|---|---|---|
| 101 | Закрыта до срока в октябре | Завершённая, без просрочки |
| 102 | Открыта, срок нарушен в октябре | Текущая и просроченная |
| 103 | Открыта, срок нарушен ещё в сентябре | Текущая, не входит в октябрьское число новых просрочек |
| 104 | Закрыта и повторно открыта | Текущая, не завершённая на конец периода |
| 105 | Срок перенесли до нарушения | Текущая, без просрочки |
| 106 | Срок перенесли после нарушения | Текущая и просроченная; перенос не скрывает нарушение |
| 107 | Закрыта только в ноябре | На конец октября ещё текущая и просроченная |
| 108 | Назначена другому человеку | Не включается в показатели EMP_001 |

Отдельно:

```powershell
python -m worklog statistics data/offline-demo/tasks-incomplete.json --employee EMP_001 --start 2026-10-01 --end 2026-10-31
```

**Ожидается:** partial=true, unavailable содержит demo:offline:109, все четыре счётчика равны нулю. Это не утверждение, что сотрудник не работал: точная история отсутствует.

## Запрос с постоянным отчётом

```powershell
python -m worklog --data-dir data/offline-demo --config data/offline-demo/config.json start --employee EMP_001 --start 2026-10-01 --end 2026-10-31
python -m worklog --data-dir data/offline-demo process <run_id>
python -m worklog --data-dir data/offline-demo report <report_id>
```

Для HTTP использовать тот же data-dir и config. Так и справочник, и результаты будут находиться в тестовой папке, а рабочая база не затрагивается.

## Что можно проверить заменой внешних систем

Уже есть автоматические проверки, в которых вместо настоящих систем поднимаются локальные тестовые серверы с вымышленными ответами:

```powershell
python -m unittest discover -s tests -p test_integrations_cli.py -v
python -m unittest discover -s tests -p test_analyzer_cli.py -v
python -m unittest discover -s tests -p test_http_application.py -v
```

Они проверяют формат запросов/ответов, авторство коммитов, признак неполного diff, передачу только подготовленного текста, отказ от выдуманных источников и меток, отсутствие утечки синтетического ключа в ошибке и работу клиента плагина с локальным приложением. Требуются только Python и, для проверки клиента, Node.js. Настоящие внешние сервисы не вызываются.

Эти проверки не заменяют проверку реальных прав доступа, версий установок, лимитов и полноты истории. Семантическое качество настоящей облачной модели ими также не оценивается.

## Пока не включаем в приёмку

- Настоящие подключения Bitrix, Kaiten и GitLab.
- Качество выводов настоящей облачной модели.
- Полное автоматическое сравнение кода и отчёта: этот сценарий ещё не реализован.
- Автоматическую очистку через Qwen и установленный плагин LM Studio: интеграция ещё не завершена.
- Codex CLI / Claude Code до реализации и проверки изоляции.

Результаты отмечать отдельно: пройдено, ошибка, не проверено или ещё не реализовано. Сам факт генерации данных не означает, что ручной тест уже пройден.
