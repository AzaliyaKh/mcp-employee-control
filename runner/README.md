# Текстовый анализатор

Реализован один adapter: text-only Chat Completions. Поставщика, адрес и модель задаёт разработчик в конфигурации по образцу `examples/analyzer.json`. Ключ берётся только из `ANALYZER_API_KEY`; пользователь и модель не выбирают поставщика. Вход — подготовленный конверт `privacy export --bundle`, без локального маппинга и справочника.

Проверки использовали только локальный тестовый HTTP-сервер. Реальный поставщик и ключ не настроены. Автоматическая смена анализатора и повтор платного запроса при ошибке не выполняются.

## Локальный протокол

```text
python -m privacy export data/work/run --bundle --output data/handoff.json
python -m analyzer --config data/analyzer.json --input data/handoff.json --output data/reply.json
python -m privacy restore data/work/run data/reply.json --json --output data/reports/report.json
```

Каталоги должны существовать. Выходные файлы не перезаписываются. Для реальной эксплуатации запускайте анализатор в отдельном ограниченном окружении, передавая туда только handoff и конфигурацию выбранного провайдера. `restore` выполняется обратно в доверенном приложении, которому доступен локальный маппинг. Не монтируйте каталог privacy-запуска в runner.

Это отдельные инструменты для проверки протокола, пока не общий автоматический task_review. В частности, интерфейс приложения ещё не направляет задачи в анализатор и не возобновляет их после решения пользователя.

## Проверка входа и ответа

- Конверт содержит только protocol, status, version, text, employee_labels и source_ids. Любые дополнительные поля, включая names, отвергаются до сетевого запроса.
- Разрешены состояния policy_checked и user_approved_exception. Проверяется SHA-256 текста. Это контроль версии в доверенном локальном протоколе, а не криптографическое доказательство отсутствия персональных данных.
- `SOURCE_001` обозначает весь переданный текстовый документ. Это ещё не доказательство на уровне конкретного коммита/строки кода.
- В запросе нет инструментов. Текст материалов рассматривается как данные; возвращаемые команды и код не исполняются.
- Принимается только завершённый JSON с summary и findings. Для каждого утверждения требуются claim, status, sources; подтверждённое утверждение должно содержать известный источник.
- Неизвестные EMP-метки и источники отвергаются. Это структурная проверка, не независимая проверка истинности выводов модели.
- Большой текст пока останавливается с объяснением: автоматическое разбиение ещё не реализовано. Вложения не передаются этим adapter.
- Диагностика HTTP не выводит ключи, адрес с webhook-секретом или тело ответа провайдера. HTTP разрешён только на loopback для проверок; реальные адреса — HTTPS, без переадресаций.

## Изоляция

`Dockerfile.analyzer` копирует только код анализатора и HTTP-транспорт, запускается непривилегированным пользователем и не содержит справочника или модулей доступа к исходным системам. Сборка и запуск образа здесь не проверены: Docker отсутствует.

Сам Dockerfile не настраивает сетевую политику, монтирования и лимиты. Перед эксплуатацией необходимы: read-only вход конкретного запуска, отдельный выход с правом записи, отсутствие исходных данных и токенов трекеров, read-only основная файловая система, лимиты ресурсов и выход только к выбранному провайдеру через принудительно ограниченный маршрут. Пока это не настроено и не проверено на целевом Linux, изоляция не считается готовой.

Codex CLI и Claude Code намеренно ещё не подключены к исполнению: смена рабочего каталога не обеспечивает требуемую изоляцию. Их не запускали и не читали внешние пользовательские конфигурации. Проверены официальные описания неинтерактивного запуска; нужные команды и аутентификацию следует закрепить вместе с версией CLI внутри будущего runner.
