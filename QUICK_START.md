# Короткая инструкция запуска

Для обычной работы на Windows, когда справочник, вебхук и MCP уже настроены. Первичная настройка и вход в Codex описаны в [BITRIX_LIVE.md](BITRIX_LIVE.md).

## 1. Открой Docker Desktop

Дождись Engine running. Docker запускает сервис и окружение облачного анализатора.

## 2. Запусти проект в PowerShell

```powershell
cd C:\Users\Azaliya\coding\ai
$env:BITRIX_WEBHOOK_URL = 'https://ВАШ-БИТРИКС/rest/ID/СЕКРЕТ/'
docker compose -f compose.bitrix.yaml up -d
docker compose -f compose.bitrix.yaml ps
```

Вместо примера укажи свой настоящий вебхук. Переменную нужно задавать в каждом новом окне PowerShell, где выполняются эти Compose-команды. Сам секрет никому не присылай.

Что запускается:

| Контейнер | Зачем нужен |
|---|---|
| service | Получает задачи Bitrix, считает статистику, сохраняет отчёты и журнал |
| codex | Выполняет явно запрошенный облачный анализ материалов |
| codex-gateway | Даёт изолированному Codex доступ к разрешённым адресам провайдера |

У service и codex дождись healthy; gateway должен быть запущен. Healthy у Codex подтверждает готовность процесса, но не авторизацию и не успешный облачный ответ.

Если нужна только локальная статистика, достаточно `docker compose -f compose.bitrix.yaml up -d service`. Она не вызывает Codex.

## 3. Открой Bionic/LM Studio

Загрузи локальную Qwen. В Settings → MCP включи employee-worklog и дождись Connected. Для рабочего режима подключение должно использовать настройки из `data/bitrix-live/mcp-entry.json`.

Qwen понимает запрос и вызывает функции сервиса. MCP-процесс приложение запускает само; отдельный терминал для него не требуется. Терминал запуска Docker можно закрыть: контейнеры запущены в фоне.

## 4. Напиши запрос в чат

Обычная статистика, без облачного ИИ:

> Покажи выполненные и текущие задачи [ФИО] с 2026-10-01 по 2026-10-31. Просроченные покажи количеством.

Отдельный облачный анализ:

> Используй analyze_employee_work: проанализируй содержание работ [ФИО] по данным Bitrix с 2026-10-01 по 2026-10-31 через Codex.

Подставь сотрудника из справочника и нужные даты. Перед облачным анализом при оставшихся персональных данных появится вопрос по названию задачи. «Нет» исключает только её, «Продолжить» разрешает отправку показанных материалов.

Если нужен облачный анализ, проверить сохранённый вход можно командой `docker exec ai-codex-1 codex login status`. Если вход не выполнен, следуй разделу авторизации в BITRIX_LIVE.md.

## Журнал и остановка

Смотреть обработку в отдельном PowerShell:

```powershell
docker logs -f --timestamps ai-service-1
```

Ctrl+C завершает только просмотр журнала. Постоянные логи запросов: `data/bitrix-live/logs`; отчёты: `data/bitrix-live/reports`. Сотрудники: `python -m employees --db data/bitrix-live/private/registry.sqlite list` из корня проекта.

Остановить проект из терминала с заданным вебхуком:

```powershell
docker compose -f compose.bitrix.yaml down
```

Справочник, отчёты и авторизация сохранятся. Не добавляй `-v`: этот флаг удаляет Docker-тома, включая авторизацию Codex.

После обновления Python-кода: `docker compose -f compose.bitrix.yaml up -d --build --no-deps service`. После обновления MCP переподключи employee-worklog; после изменения его инструментов начни новый чат.
